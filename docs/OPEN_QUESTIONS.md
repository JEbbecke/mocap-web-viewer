# Open questions and scientific limits

1. The current H5 declares global force vectors. Other unresolved force frames are never inferred from converter names or placeholder poses. Signal inspection remains available; spatial display requires explicit stored-global confirmation, which does not establish a conversion convention. Unresolved frames block C3D→H5 or omit the affected H5→C3D plate.
2. The current layout is unversioned, with expanded Events and nested metadata; obsolete versioned layouts are rejected. Body parent frames and Type codes are unestablished. Model units require explicit metadata or the disclosed limited IK rotation convention. IK/ID clocks are classified separately: proven trajectory-aligned results crop with the trial; independent or unknown relationships retain the source clock and samples without a guessed shift.
3. Marker and body units must be declared. Missing residuals cannot establish whether finite zero coordinates are true origin samples; missingness is not guessed.
4. Missing or empty GlobalCoordinateSystem does not establish lab handedness or compass directions; lab XYZ is retained and Z-up is a camera convention. Explicit descriptions are copied as metadata without rotating values. Never apply the converter's OpenSim -90° rotation during viewing.
5. Scientific comparisons use independent ezc3d/C3D raw records and current H5 raw datasets, preserving missing values and actual geometry. Display helpers are not independent scientific oracles.
6. No source measurements may be committed/deployed. Local integration comparisons are opt-in; CI uses synthetic fixtures.
7. Installed ezc3d 1.7.0 decodes positive floating point residual magnitudes inconsistently with the published C3D format (reproduced with a synthetic 2.0 fourth word). Web uses the standard conversion and retains validity; exact values and reproduction are in VALIDATION.md. H5 may already contain an exporter-decoded residual; no correction is guessed without raw C3D records.
8. Crop export supports current H5 Events and explicit Time datasets. Unknown event schemas, undocumented time-series datasets and unestablished timing attributes remain guarded. Unknown C3D vendor parameter groups are retained but proprietary temporal parameters are not adjusted; confirm vendor conventions before downstream use.
9. Active C3D FORCE_PLATFORM:ZERO intervals must remain inside the crop. Supporting their removal requires an independently validated baseline/calibration policy rather than silently changing force values. Segmented EVENT arrays remain unsupported for crop export.
10. Independent h5py validation checks authoritative H5 exports. End-to-end interoperability with an external current institute reader remains a manual check. Modified exports can change chunks/maxshape while preserving supported scientific dtypes and values, including boolean enums. See H5_VALIDATION.md.

11. Legacy C3D type-2/3 channels may retain V acquisition labels after force calibration. JE Motion Lab retains the validated QTM/C3D/ezc3d calibration convention without warning solely about V labels; labels alone cannot verify a malformed file's actual calibration. See [unit policy](UNITS.md). Type-4 moment matrix rows must match the POINT length unit.
12. Cross-format conversion is limited to imported normalized data. H5→C3D cannot represent moving plates, arbitrary signal grids, rigid bodies or IK/ID; quality and raw trees can be omitted. Original force-channel reuse requires matching embedded definitions and reconstruction; the TYPE-2 fallback can lose differing stored COP/free moment. Custom JE_METADATA is readable by JE Motion Lab but not promised in other readers' metadata interfaces. See [compatibility and loss reporting](CROSS_FORMAT_EXPORT.md).

See [event visualization and editing](EVENT_EDITING.md) for immutable event operations, relative-second timing, C3D serialization and the current institute H5 event layout.

# Authoritative H5 lifecycle validation

Validated locally on `feature/h5-data-structure`, 25 September 2026: 60 tests
passed across seven suites; production build, Chromium lifecycle/plot checks and
eight independent Python comparisons/checks passed. The source
was opened read-only, remains ignored by Git, and was never uploaded. Tests
compare its bytes before and after processing. Private inventories, exports,
browser logs and Python reports stay in ignored `.local/`.

## Evidence and reproducibility

- `node scripts/inspect-h5.mjs` traverses all 60 objects (including root), records
  every attribute, dtype, dimension, encoding, compression and numerical summary.
  The private inventory was created before application changes; the schema was
  documented in H5_FORMAT.md before implementation.
- `npm test`: the populated-schema suite compares every dataset recursively,
  including boolean enum definitions, integer widths, float64 values, Unicode
  strings, attribute types and shapes. Synthetic fixtures cover optional groups,
  all boolean-field combinations, unknown arrays/scalars/attributes, unknown event
  columns, invalid dimensions, event CRUD, physical-time crops and legacy files.
- `npm run build`: TypeScript and production bundle.
- `npm run test:browser`: Chromium runs actual local import/export workers on
  synthetic and authoritative H5 files. Checks unchanged export, event edit,
  add, delete, downloads, re-import, one-frame cropping and available plots.
  It checks runtime errors, GET-only bundled-asset traffic and empty browser
  storage. No file contents or metadata are transmitted.
- Run `scripts/validate-authoritative-h5.py` with a local Python containing
  h5py/numpy after the tests. It independently compares the full hierarchy using
  exact values (NaNs equal), all shapes, dtypes, enum/string metadata and
  attributes. It also inspects the browser downloads. The installed institute
  reader is tried without modification.

The synthetic fixture and empty boolean templates are generated by
`scripts/create-h5-fixture.py` and `scripts/create-h5-boolean-seeds.py`. They contain
only invented values and names. Python is a development oracle, not an application
dependency; import/export is entirely local browser JavaScript/WASM.

Event times are relative to the current recording only inside MotionData/UI;
the H5 keeps absolute source times and frames. Untouched event timestamps and
frames are copied exactly, avoiding an unnecessary floating-point round trip.
Marker rendering uses metre-valued float64 arrays, while raw float64 source
coordinates back export. Display conversion is not applied to exported values.

## Expected differences and limits

Edited H5 files have fresh binary storage. Boolean templates preserve the exact
enum but use different chunk shapes and unlimited maximum dimensions. Cropped
numeric datasets can have smaller chunks/maxshape. These storage differences
are classified separately from scientific differences by the Python report.
Compression is retained for supported numeric datasets. The reference has no
unpreserved scientific dataset, attribute, dtype or value in the tested paths.

This is support for the observed institute schema, not arbitrary HDF5. Unknown
primitive datasets/attributes survive unchanged and event-only export. Unknown
time-dependent content blocks cropping rather than being silently mistimed.
Arbitrary enum/compound/reference/opaque types, named types, null dataspaces,
link identity and arbitrary filter pipelines are not guaranteed in modified
exports. Unchanged export preserves all original bytes. Irregular point clocks
are rejected because current frame playback requires regular marker sampling;
other signal clocks may be irregular.

Source processing metadata is preserved as opaque text. For example, IK Metadata
contains an original nRows value; the structural NumSamples attribute is updated
on crop, while the opaque processing record is retained unchanged. No new history
or inferred model units are fabricated.

The file does not establish lab compass directions/handedness, body parent frames,
Type codes or per-channel IK/ID units. The reference explicitly declares global
force/free-moment coordinates, and the application applies no additional rotation.
Bodies are exposed as position signals and structured rotations/membership; they
are not rendered as an invented skeleton. Existing marker, plate, GRF and COP
rendering is reused.

## Python compatibility

h5py reads every output and independently confirms the comparisons above. Both
the sibling and installed institute H5 readers expect `Location`/`Offset` and fail
with a missing-Location KeyError on the **unchanged authoritative file itself**.
Edited and cropped outputs fail at the same point. Consequently compatibility
with that old application cannot be claimed. Neither the Python application nor
the authoritative schema was changed to conceal this mismatch. The current reader
that produced the reference is needed for an end-to-end institute application check.

## Manual checks before a PR

1. Inspect marker gaps, plate outlines, COP and force signs in your normal lab view.
2. Inspect EMG/free-moment/body and IK/ID plots; confirm the model clock mismatch
   reflects the intended source data and determine missing model units externally.
3. Edit/add/delete events, crop around event boundaries, export/reopen, and restore
   the original recording. Check crowded events and keyboard controls.
4. Open downloads with the current institute reader that supports Corners/Origin,
   vector Tz and event schema 1; the locally installed legacy reader cannot do so.
5. Confirm only synthetic fixtures and schema-level documentation enter the PR.
   Keep `reference-data/`, `.local/` and private downloads excluded.

## Moving-plate regression

`tests/moving-plates.test.ts` creates a participant-free H5 with translating and
tilting global corners/pose at 100 Hz, forces at 200 Hz, a nonzero source clock
and a sensor origin below the plane. It checks all corner samples, display
interpolation, static pose layouts and crop/export/re-import synchronization.
After `npm test`, the browser smoke check loads that fixture and compares canvas
images with plates hidden/visible and across three geometry frames, including
movement outside the marker envelope. Images remain in ignored `.local/`.
